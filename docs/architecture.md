# Architecture

This document is for contributors. Sigma is a static, client-only Preact app: there is no backend.

## Principles

1. **Light first.** The precached app shell is about 200 KB. Every screen, dialog and heavy library is a lazy chunk, fetched the first time it is needed.
2. **Data never leaves the device.** State lives in IndexedDB; the only network traffic is downloading code.
3. **Arabic first, fully bilingual.** RTL is the default; layout uses logical CSS properties throughout.
4. **Trustworthy numbers.** Statistics come from SciPy/NumPy (via Pyodide) and are tested against reference values.

## Layout

```
src/
  main.jsx               boots: loads the active language, renders <App>
  App.jsx                shell: header, tabs (lazy), mobile bottom nav, global toasts
  components/
    Grid/DataGrid.jsx    virtualised editable grid (desktop Data/Variable views)
    Charts/svg/          tiny SVG chart kit (axes, bars); charts render into it
    Analyze/             one lazy dialog per analysis
    Engine/              engine download progress + offline panel
    Welcome/             first-run screen (sample dataset, import, start empty)
    LazyBoundary.jsx     Suspense + recoverable error UI for lazy chunks
  lib/
    pyodideLoader.js     public engine API: getPyodide(packages), ensureEngine, …
    engine/
      manifest.js        GENERATED by scripts/gen-engine-manifest.mjs from the pinned pyodide
      plan.js            which files/packages an analysis needs (pure)
      download.js        byte-progress downloads into Cache Storage
      handlers.js        worker message handlers (also tested in Node)
      engine.worker.js   Web Worker entry
    stats/*.js           one module per procedure; Python code runs in the worker
    expression.js        safe formula evaluator for Compute Variable
    pdf/                 PDF export (jsPDF) + Unicode bidi reordering for Arabic
    charts/              chart data prep + scales
    importFile.js        CSV/XLSX parsing (parsers lazy-loaded)
    exportDataset.js     CSV/XLSX export (writers lazy-loaded)
  store/                 Zustand stores: dataset (with undo), results, filter, engine
  db/                    ~1 KB IndexedDB wrapper + debounced persistence
  i18n/
    locales/{ar,en}.json UI strings (only the active one is loaded)
    help/{ar,en}.json    Help-page texts (loaded with the Help tab)
```

## Statistics engine

```
Dialog ─► getPyodide(ANALYSIS_PACKAGES.ttest)
            │ plan.js: core? numpy? scipy? (minus what's loaded)
            ├─► download.js: fetch missing files with progress → Cache Storage
            ├─► worker: init (loadPyodide) / loadPackages
            └─► facade { toPy, globals.set, runPythonAsync } ─► worker "run"
```

- `ANALYSIS_PACKAGES` in `lib/engine/plan.js` maps each analysis to its Python packages.
- Python runs in a Web Worker, so the UI never blocks.
- Engine files live in the `pyodide-<version>` cache, shared with the service worker (CacheFirst), so downloaded parts work offline.
- To upgrade Pyodide: bump the `pyodide` devDependency, run `yarn engine:manifest`, and update the CI `pip install` pins to the matching NumPy/SciPy versions.

## PWA and caching

`vite.config.js` contains two small build plugins:

- **offline-assets:** splits the output into the *initial* shell (precached by Workbox on install) and *lazy* chunks (runtime-cached on first use, and listed in `offline-assets.json` for the "download everything" button).
- **asset-links:** emits `/.well-known/assetlinks.json` for Google Play when the `TWA_*` env vars are set.

Updates use `registerType: 'prompt'`, so a new version never reloads the page in the middle of work. `vite:preloadError` triggers a one-time reload if a deployment removed an old chunk.

## i18n and RTL

- `i18n.js` keeps `<html lang/dir>` in sync with the language.
- Use logical CSS properties (`inset-inline-start`, `margin-inline-end`, `text-align: start`), never left/right.
- Charts and numeric cells are deliberately LTR (`dir="ltr"`).
- PDF text goes through `lib/pdf/bidiText.js` (shaping and the Unicode Bidi Algorithm).

## Testing

`yarn test` (Vitest) runs:
- pure unit tests (planning, downloads, expressions, bidi, scales, import naming)
- worker handlers against the real Pyodide from `node_modules` (offline)
- every stats module's Python code under CPython + SciPy 1.14.1 (the version Pyodide ships); these are skipped if SciPy isn't installed

CI (`.github/workflows/ci.yml`) runs lint, tests and build on every PR.
